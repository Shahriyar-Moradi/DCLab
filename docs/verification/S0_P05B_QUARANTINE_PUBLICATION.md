## Remaining decision and safe boundary

The existing Labs upload immediately previews, creates a Dataset with nullable/unknown policy labels, and queues training. The plan requires unknown classification to deny preview and download. Automatically marking those uploads `classified` or `published` would invent a data-policy grant; blocking them changes the current immediate-training product flow. A product decision is required: hold all new uploads in quarantine pending authorized classification, or define and review a separate internal-only deterministic-training policy that does **not** grant preview/download/LLM exposure. Until decided, development keeps the current compatibility path; production refuses new Labs uploads, uploaded trial data, admin dataset uploads and legacy opportunity CSV import, and enforces publication on materialization/download. Existing unverified production datasets may become unavailable (not deleted) and require audited forward repair. No scanner, classifier, resume worker, UI or publication enablement has been represented as complete.
