End-state architecture

Every client goes through the same API; agents only propose

Studio, Claude Code and the CLI all reach the same /v1 API. Training, agents and scoring run only in the worker. Agents send typed proposals to the proposal service; a command service carries out a change only after a person or a policy accepts it.

Phase 1 · done locallydeterministic

Upload a CSV, get a model you can defend

The engine profiles the data, holds out the latest three months, audits leakage on the training part only, runs a dummy baseline plus real candidates under CV, chooses the decision threshold from out-of-fold scores, then scores the holdout exactly once.

Phase 3 · doneexternal agent

Claude Code drives the whole project over MCP

The first agentic milestone. DCLab calls no LLM here: Claude Code is the agent, and about 14 MCP tools are its hands. The service token limits it to one workspace and a set of capabilities, and read/write kill switches can turn it off.

Phase 5 · planneddeterministic proposer + Optuna

State a goal; the loop runs audited iterations

Goal: maximize precision while keeping recall ≥ 0.80. Each iteration is a child experiment with a typed change set, a reason, a result and a cost. Iterations are judged on CV only. The holdout is used once, for the final pick.

Phase 6 · plannedinternal agents · LLM

Agents write cited proposals; a validator checks them; you decide

Four NOOA agent classes make one structured LLM call each, under DCLab budgets. A validator checks every cited column and metric before a proposal reaches the inbox. Jev answers small typed questions in shadow mode until each question passes its release gate. With agents and Jev turned off, every Phase 1–5 feature still works.

Phase 7 · planneddeterministicagents explain

Release to batch scoring, watch drift, roll back in one step

Models are packaged safely (skops/native, with a data contract). Scoring runs as batch jobs in the worker; the API never loads a model. Monitoring windows compute drift. A drift alert opens an investigation, and a retrain becomes a normal experiment on the same split rules.

Not yet in the plan

Gaps this tour exposes

  • Feature-engineering leakage contract. Target encoding, history aggregates, lag/rolling features and point-in-time joins have no design yet. They need declared fit scopes and as-of cutoffs before agents may propose new features (suggested home: ADR 0007 or a P5.0 prompt).
  • Prediction-time availability. The Phase 7 feature contract checks types, not when a value becomes known.
  • AI-first reordering. Moving the agent core and Jev earlier (discussed, not adopted) would change Phases 3–6. Today, built-in agents arrive in Phase 6.
