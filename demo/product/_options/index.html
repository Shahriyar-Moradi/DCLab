DCLab demo redesign · four directions

Four different answers to the same brief: keep every detail of version 2, make it clearer, cleaner and better organized, and modern without being flashy. Each direction is shown on the same two screens (Home, and one experiment) with the same invented Northwind data. They differ in structure, not just colour. Pick one, or name the pieces you want combined.

Kept in every direction

  • All of version 2's content: every number, candidate, check, decision and event.
  • The guide: what the screen is for, how to use it, the next step. Lighter than v4, never a wall of text.
  • Rule beside AI: wherever an agent proposes, the deterministic answer sits next to it.
  • Plain words first, ids second (E7 · SP-1 stay visible but small).
  • Light theme shown; each has a dark theme in the real build.
  • Same screens as today: Home, Inbox, Lab, Data, Pipeline, Experiments, Improve, Graph, Models, Monitoring, Decisions, Governance, Agents, Settings, Outcomes, Operator.
Direction A

Editorial

A calm, document-like product. One narrow reading column, a serif headline, hairline tables instead of boxes inside boxes, and a quiet right rail that carries the guide and the next step. Feels like a well-typeset report that happens to be interactive.

Structure

  • Left: text sidebar, workflow steps numbered 1–7 with done ticks.
  • Middle: one column, max 1040 px, sections separated by rules, no cards.
  • Right: fixed rail with About, How to use, Next step, Terms.

Palette

Warm off-white, near-black ink, one deep green accent, indigo for AI.

Strong when

  • You want the product to feel trustworthy and unhurried, like evidence rather than a dashboard.
  • Reading long tables and findings is the main job.
  • You want the fewest visual elements per screen.

Trade-offs

  • Least "app-like"; dense screens (Pipeline, Governance) become long scrolls.
  • No persistent assistant panel; chat lives on the Lab screen only.
  • Serif headlines are a taste call.
Direction B

Workbench

A three-pane developer tool, like Linear or an IDE. A thin icon rail, a project panel that shows the versioned state graph as a vertical chain with live status dots, the main pane, and a docked assistant on the right that stays with you on every screen. Compact type, everything in its place.

Safest for detail

Structure

  • Rail 52 px → project panel 236 px (state graph + experiments tree) → main → assistant dock 320 px.
  • Panels with segmented controls (Table/Cards, Mean/Per fold) instead of tab strips everywhere.
  • Guide and next step live in the dock, above the chat.

Palette

Cool neutral greys, indigo accent, violet for AI, dark rail.

Strong when

  • Developers are the main audience and want the most on one screen.
  • The state graph in the sidebar is the mental model you want people to learn.
  • The assistant should be present everywhere, not a separate page.

Trade-offs

  • Smallest type; least friendly for business users (Outcomes would need its own simpler shell).
  • Four columns need a wide screen; on laptops the dock collapses to a button.
  • Looks like other developer tools, so less distinctive.
Direction C

Flow

The versioned state graph is the product, so it becomes the navigation. Every project screen starts with the chain Data → Goal → Split → Features → Experiments → Champion → Release → Monitoring; green is done, purple is running, amber needs you. Click a step to open it. Soft surfaces, rounder corners, bolder headlines, one gradient used sparingly.

Recommended

Structure

  • Sidebar: workspace items + project list with status dots; project sub-items only when inside one.
  • Flow bar at the top of every project screen; Home shows the full flow of the active project.
  • Guide is a three-column strip at the bottom of the main card: What you see · How to use it · Next step.

Palette

Cool white, near-black primary buttons, teal → violet gradient for brand and AI, amber for "needs you".

Strong when

  • You want the demo to explain DCLab's idea (versioned steps, decisions attached) without a guide paragraph.
  • You want a distinctive, modern product look that still reads at a glance.
  • Both developers and business users land in the same shell.

Trade-offs

  • The flow bar costs ~70 px of height on every project screen.
  • Branches and nine experiments need a compact "E7 of 9" treatment inside one node.
  • Gradients and soft shadows must stay restrained or it tips into "too much".
Direction D

Console

Decisions first. Home is a stream of what needs you and what the AI did on its own, newest first, with the selected item's evidence and Approve / Reject in a fixed right pane. A top navigation bar instead of a sidebar frees the full width for the two columns. Warm stone neutrals, one terracotta accent.

Structure

  • Top bar: Inbox · Projects · Decisions · Governance · Agents · Settings. Project screens add a second row of tabs plus state chips (DS v3 · SP-1 · E9 running).
  • Home = stream (left) + evidence pane (right) with the rule beside the AI and a chain of events.
  • Project screens = main + a "Decisions on this run" pane; guide sits under it.

Palette

Warm stone, near-black, terracotta for "needs you", indigo for AI, green for approve.

Strong when

  • The story you want to tell is "humans decide, AI proposes, rules enforce".
  • Users have several projects and care about the queue more than any one project.
  • You want the evidence for a decision visible without leaving the list.

Trade-offs

  • Projects feel secondary; a new user looking for "my model" has one more click.
  • Top navigation holds fewer items, so some screens move under Projects or Governance.
  • The two-pane Home needs ≥ 1200 px; below that the evidence pane becomes a drawer.
