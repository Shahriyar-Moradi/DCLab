One screen, Churn prediction: the list, how much to trust it, questions, and a plain-language description of the model. No experiment details.

Operator

One screen, Operator console: workspaces, jobs, held uploads, platform limits and quality gates. Metadata only.

What the design assumes but the plan does not cover yet

  • Reasons per customer. The business list shows "main reasons". That needs a deterministic explainer in the engine.
  • Real outcomes for monitoring. "Upload outcomes" exists as a button; the path (upload, connector or labeling) is undecided.
  • Notifications. Email and in-app are shown; no delivery service is planned yet.
  • Plain-language summaries. Start from fixed templates; add generation only if it saves time.
  • Data cleaning. "Remove duplicates" is a button; who owns cleaning steps is open.
  • Workspace-level decisions. Policy changes need the same history as project decisions.
  • Analyst role. Shown in Settings; not in the current role model.
  • Conversations that continue. What the Lab does when the user leaves mid-run.

What was removed to keep the product clear

  • Separate Pipeline, Improve, Decisions and Agents screens. They are tabs now.
  • Record ids, file digests, prompt versions and token counts on main views. They stay in exports and the audit report.
  • Trust-level codes. The product says "Observe", "Ask first" and "Automatic".
  • Manual tuning forms. The improve loop covers them.

Not in the first release

Each needs a customer trigger and its own decision.

Live scoring APIThe first release scores files on a schedule.
Connectors to databases and CRMsThe first release uses file upload and the API.
Forecasting and text dataThe first release covers tables: yes/no, categories and numbers.
Assistants that write their own feature codeNeeds a separate sandbox.
Notebooks, external GPUs, a second cloudOn demand.
